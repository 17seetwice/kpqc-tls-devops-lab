그림 1. 정책 기반 KPQC TLS 배포 검증 시스템. 점선은 SSH 및 경로 제어, 굵은 실선은 클라이언트와 서버 사이의 TLS 시험 연결을 나타낸다. GitHub Actions는 시험 증적을 수집해 서버의 배포 게이트에 제출한다. 두 EC2는 서울 리전의 동일 가용 영역에 위치한다.

그림 2. 후보 배포 및 검증 절차. 게이트는 Provider 가용성, 필수 클라이언트의 TLS·인증서 검증 결과와 실제 협상 파라미터를 검사한다. 승인 시 활성 경로를 전환하고 새 인증서로 재검증하며, 거절 시 기존 서비스를 유지한다. 마지막 정리는 실험 종료 단계다.

실험 설정: TLS 1.3, SMAUG1, HAETAE2, TLS_AES_256_GCM_SHA384. 기존 서비스와 정상 후보는 같은 암호 조합을 사용한다. 그림 2는 후보 한 개의 판정 흐름을 나타낸다. GitHub의 CD는 수동 시작하며 사전 빌드·시험 성공 후 진행한다.
