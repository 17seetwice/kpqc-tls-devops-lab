# 문서 3차 검토 기록

검토일: 2026-09-25

대상: `PROJECT_WALKTHROUGH.ko.md`, 해당 HTML, 루트 `README.md`·`README.en.md`.

## 1차: 구현과 설명 대조

- `tls_handshake.c`에서 fresh 조건의 클라이언트 실행과 서버 연결별 fork를 확인하고, 서버 전체를 매번 재시작한다는 오해가 없도록 수정했다.
- TLS 호출 전 시험용 준비 신호와 경로 선택 문자열을 설명하고, SSL_connect 계측 경계와 일반 HTTPS 접속 절차를 구분했다.
- `gate_suite.py`의 인증서 부정 시험은 증적의 지문 변조임을 확인했다. 실제 이름 오류·만료·신뢰 체인별 주입 시험을 수행한 것처럼 읽히는 설명을 수정했다.
- 최종 배포 실험의 tmpfs 개인키 보관, 프로세스 그룹 장애, 동일 EC2의 이전 서비스 및 새 연결 대상 전환이라는 범위를 유지했다.

## 2차: 수치와 해석 검토

- 초기 및 균형화 `summary.csv`에서 기준선·KPQC 구성별 중앙값 범위를 다시 계산해 본문과 대조했다.
- 메모리 CSV의 KPQC 중앙값 범위(클라이언트 648–980 KiB, 서버 628–1,252 KiB)를 확인했다.
- `scripts/audit_release.py`로 공개 원자료의 후보별 판정을 재계산했다. 각 후보 300회 성공, 정상 두 후보 승인·350ms 지연 후보 거절, 검증 24개, 장애 감지 1.596초·복구 2.951초·150회 중 21회 실패가 일치했다.
- 네트워크 표는 세 블록 중앙값의 중앙값, HRR 차이는 블록별 대응 차이의 중앙값임을 명시했다.
- README에 검증 질문·방법, 균형화 핸드셰이크 결과 및 전체 설명 링크를 추가했다. TLS 호출 지연과 배포 접속 완료 시간을 별도 표로 유지했다.

## 3차: 문서 일치와 배포 준비 검토

- 수정한 Markdown에서 HTML 본문을 다시 생성하고 렌더링된 본문 문자열의 일치를 확인했다.
- 대상 네 파일을 UTF-8로 읽고 대체 문자(U+FFFD)가 없음을 확인했다.
- 상대 경로 링크와 이미지 경로의 존재, `git diff --check`를 확인했다.
- 한·영 README의 추가 질문, 수치, 복구·키 관리 범위를 대조했다. 전체 walkthrough는 한국어 자료라는 점을 영어 README에 명시했다.

이번 작업은 기존 기록과 코드에 대한 문서 검토다. AWS 재실행이나 새로운 성능 측정은 하지 않았다. HTML의 브라우저 화면 배치 검사는 이번 검토에 포함하지 않았다. GitHub에는 아직 업로드하지 않았다.
